# gomtm Skills Improve

## 核心原则

把技能维护成可验证的编辑闭环：先证明问题，再做最小改动，最后用同一证据复核。`SKILL.md` 只承载每次运行都需要的步骤和选择规则；分支专用细节通过明确的上下文指针按需披露。

## 必做流程

### 1. 盘点

先标记本次模式：请求授权落地修改时选择 `edit`，在授权文件内实施；其余请求选择 `review-only`，只产出证据、结论和建议。读取目标 `SKILL.md`、仓库指令、README、验证入口，以及本次分支会使用的直接引用文件；枚举目录中的其余资源和 `copy`、`backup` 等候选权威文件，判断它们是否受影响。

**完成条件：** 模式、授权文件、验收目标、调用方式、任务分支、事实来源和目录资源均已记录；每个资源都有“已读取”或可验证的“不适用”理由，每个候选权威文件都有唯一角色。

### 2. 诊断

对照真实源码、官方文档、仓库 README 和用户报告验证问题。行为引导发生变化时，先锁定修改前的不可变内容快照，再在不透露预期修法的新上下文中，用一个代表性任务运行该快照，固定记录任务输入、环境与上下文、快照标识、期望行为和实际结果；纯措辞、路径或格式修正以解析结果、路径检查或 diff 作为基线证据。目标技能自我改进时，基线只加载修改前快照。

逐项检查：

- **调用：** invocation 模式是否正确；description 是否以稳定 leading word 开头，并为每个真实分支保留一个触发条件。
- **层级：** 每次运行都需要的步骤是否内联；分支专用 reference 是否由可观察条件触发；相关规则、例子和 caveat 是否共置。
- **执行：** 流程顺序是否明确；每一步是否以可检查、必要时穷尽的完成条件结束。
- **修剪：** 每个含义是否只有一个权威位置；逐句标记重复、失效内容、no-op 和否定式塑形。

**完成条件：** 每项计划改动都对应一个观察失败、权威事实或验证失败，并能从证据追溯到建议改法。

### 3. 编辑

`review-only` 输出按证据排序的发现与最小补丁建议；`edit` 应用能满足证据的最小补丁。保持原技能的主要语言，使用正向输出契约描述目标行为，并按下表维护单一事实源。必须阻止危险行为时，硬边界同时给出可执行的替代动作。

**完成条件：** `review-only` 交付逐项证据映射和“已验证/待落地验证”标记，存在发现时附最小建议稿，无发现时明确无需修改；`edit` 的每个适用交付物满足下方质量契约，且 diff 仅覆盖授权范围。

### 4. 验证

先标注每条命令的联网、依赖安装、缓存写入、仓库写入和外部状态副作用；`review-only` 执行当前授权覆盖的只读检查，把其余命令及所需授权列为待运行；`edit` 在实现授权内运行仓库校验和受影响资源检查。

在 mtmskills 仓库先运行：

```bash
git diff --check
```

当授权覆盖 npx 的联网、下载和缓存副作用时，再运行发现检查：

```bash
npx -y skills add . --list --full-depth
```

确认命令退出码为 0，且目标技能恰好出现一次。继续检查 frontmatter 可解析、`name` 与目录一致、相对引用存在、模板可由对应解析器读取、脚本可执行且输出符合约定，并让 secret 扫描与可移植性检查返回干净结果。`edit` 模式修改行为引导时，在另一个不含预期答案的新上下文中，用第 2 步的同一任务和判据复测；目标技能自我改进时，复测只加载修改后快照。`review-only` 为建议稿给出相同输入和判据的可执行复测计划。记录每条命令、副作用、退出码和关键结果；无关既有失败单独列出其证据和影响范围。

**完成条件：** `review-only` 为当前态检查提供证据，为建议稿提供可执行验证计划，并把未落地项、命令副作用和所需授权标为待验证；`edit` 的行为变化由锁定的修改前后快照及隔离的同场景复测闭环，机械修正由解析结果、路径检查或 diff 闭环。两种模式都要隔离与本次范围无关的失败，并在交付说明中覆盖每个审查或修改文件及未解决项。

## 内容的权威位置

| 内容 | 权威位置 | 质量契约 |
| --- | --- | --- |
| 调用条件与分支 | frontmatter `description` | 只写触发；一个真实分支一个条件 |
| 所有分支都需要的步骤、边界和选择规则 | `SKILL.md` | 保持入口化；步骤以完成条件收束 |
| 仅特定分支需要的背景、排障和深入解释 | `references/*.md` | 从 `SKILL.md` 直接指向，并写明读取条件 |
| 可复制配置和交付物起点 | `templates/*` 或 `assets/*` | 提供完整起点；用注释表达可选分支 |
| 重复、脆弱或需要确定性的操作 | `scripts/*` | 明确“执行”或“阅读”；实际运行验证 |
| 技能列表和入口的 UI 元数据 | `agents/openai.yaml` | 与 `SKILL.md` 保持一致；按仓库生成器校验 |

正文面向专家，提供判断规则、关键命令和真实坑点。路径使用 `references/...`、`templates/...`、`scripts/...` 等技能相对形式；跨仓库路径使用仓库相对路径或 `<repo>/...`。示例使用 `<service>`、`<host>`、`<repo>`、`SERVICE="..."` 等稳定占位符，并保留一个完整、正确、可迁移的例子。

## 失效信号

| 观察 | 修复 |
| --- | --- |
| description 复述正文流程 | 收敛为触发条件，让正文承载执行步骤 |
| 步骤以“理解、检查、改进”结束 | 改成可观察产物、命令结果或穷尽清单 |
| 同一事实散落在正文、模板和 reference | 选定一个权威位置，其余位置只保留上下文指针 |
| 必需材料藏在“另见某文件”之后 | 在指针中写明触发读取的可观察条件 |
| 规则只说“专业、准确、全面” | 用输出结构或完成条件替换 no-op |
| 塑形语句围绕“不做什么”展开 | 正面描述目标输出；硬边界附上替代动作 |
