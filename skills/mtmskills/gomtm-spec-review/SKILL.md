# gomtm Skills Improve

## 何时使用

- 当用户提及类似于"对规格文档,开发计划文档进行审查"的时候
- 当原任务要求需要对规格文档或者开发计划文档进行额外review,而且检查确认的时候.

## 规格文档来自哪里

可能来自:

- 由 `$superpowers:brainstorming` 技能编写的规格和计划文档的约定路径, 通常是: `docs/superpowers/specs/` 和 `docs/superpowers/plans/` 目录下.

## 如何进行review

- 当本次对话完成了规格或者开发计划文档的编写, 使用 sub agent 的方式委派独立的工作者进行独立审查. 对 sub agent 的最终结果进行确认并修正, 最多进行**三次**
- 当本次对话没有进行过规格或者计划文档的编写, 那么依据原任务提供的指引找到文档直接在本次对话完成审查.
- 当找不到相关文档, 应要求人类大胆提供更加准确的地址. 而不是胡乱猜测文档地址.

## 重点审查范围(检查清单)

1. [ ] 规格和计划文档的正确性, 符合开发目标,符合原始想法.
2. [ ] 规格和计划文档的完整性, 没有遗留关键步骤, 逻辑自洽.
3. [ ] 确认没有双重实现. 没有平行实现, 没有重复造轮子.
4. [ ] 当原任务提供了验收标准, 必须符合验收标准, 否则可以跳过此项.
5. [ ] 除文档已明确的风险外没有额外的重大风险.
6. [ ] 符合已知的开发约定, 符合项目文档规定.

## 要求

1. 必须以独立的视角独立进行, 不要轻信原文档的正确性.
2. 对文档的相关依据,源码,和文档进行确认.
