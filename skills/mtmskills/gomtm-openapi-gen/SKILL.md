# gomtm OpenAPI Generation

## Overview

`gomtm-openapi-gen` owns gomtm OpenAPI artifact refresh work. The workflow is intentionally kept as agent-run shell scripts under this skill so the public `gomtm` CLI remains focused on runtime, deploy, database, install, and operational commands.

The canonical committed OpenAPI artifact is:

- `pkg/clicmd/openapi.json`

That file is embedded by `pkg/clicmd` to register OpenAPI-driven CLI commands. Regenerate it when route schemas, route options, request/response models, or Fuego OpenAPI metadata change.

## When to Use

- A gomtm route, request model, response model, or `routeopts` CLI extension changed.
- `pkg/clicmd/openapi.json` needs to be refreshed before committing API/CLI changes.
- An external consumer explicitly needs a temporary Go REST client generated from the current spec.
- A review asks whether embedded OpenAPI CLI metadata is current.

## Scripts

Run scripts from the repository root:

```bash
bash .agents/skills/gomtm-openapi-gen/scripts/generate-openapi.sh
```

Optional full workflow:

```bash
bash .agents/skills/gomtm-openapi-gen/scripts/generate-all.sh
```

Optional external Go REST client generation:

```bash
bash .agents/skills/gomtm-openapi-gen/scripts/generate-rest-client.sh /tmp/gomtm-rest-client
```

## Artifact Policy

- Commit `pkg/clicmd/openapi.json` when route/CLI metadata changes.
- Do not reintroduce a public `gomtm gen` command for this workflow.
- Resolve the repository root through git and use the standard Go build cache unless the caller explicitly sets `GOCACHE`; refuse any `GOCACHE` under `.agents/`.
- Do not add `oapi-codegen` or generated client packages back to gomtm `go.mod` for optional external clients; scripts may use `go run <module>@<version>` directly.
- External client output should normally live outside the gomtm repo or under an explicitly temporary path.

## Verification

After regenerating the spec, run the focused checks:

```bash
go test ./pkg/clicmd ./cmd -count=1
```

When route registration changed, also run:

```bash
go test ./pkg/... -count=1
```

## Common Pitfalls

1. **Running stale CLI commands.** OpenAPI generation is skill-owned; use the scripts in this directory.
2. **Generating clients into gomtm by default.** The main repo embeds the spec. Client packages are generated only when a real external consumer needs them.
3. **Using floating generator versions.** Optional client generation pins the `oapi-codegen` version in the script.
4. **Leaving temporary Go files behind.** `generate-openapi.sh` installs a trap and removes its temporary test helper on exit.
5. **Writing caches under `.agents/`.** If Go cannot use its normal cache, fix `go env GOCACHE` or the environment; do not redirect caches into the skill library or project source tree.
