# 概述

如何正确设置磁盘空间.

1. 有些 vps 提供商会将linux 系统的磁盘分为系统盘和数据盘, 数据盘可能会挂载挂载到特定路径,例如`/data`. 应当分析vps的数据盘的路径进行软连接等相关配置, 将系统的相关对磁盘占用比较多的文件罗盘到数据盘,但是依然保持原有的路径,以维持原有的路径不变. 如果没有额外的数据盘，则不用理会，按照单磁盘的方式进行。

2. 已知需要处理应当落盘到数据盘的数据有.
  - docker 全局数据目录. 方法: 重新设置docker的配置文件,并重启docker服务.
  - 项目源码跟目录: `/workspace`, 这个目录一般用户日常开发, 会用于 git clone 各种私有或者公有仓库, 占用空间较大.
  - 开发和语言运行时, 例如, nodejs npm python pip uv golang java gradle,android-sdk,ndk 等, 这些工具的缓存和运行时数据一般会占用大量空间.

  - `~/.local/`


# 什么时候应当进行磁盘空间管理

1. 当用户明确提出需要进行磁盘空间管理时.
2. 在开通新的 linux 服务器,进行初始化设置时.
3. 当系统磁盘空间不足时.

## 已知可以安全删除的文件有

- /tmp/go-build*
- /tmp/ 目录下48小时前创建的文件且没有被其他进程使用的文件.

## 已知应当移动到数据盘的文件有
暂无固定项目专用目录；按实际磁盘占用确认后再处理。

## 禁止删除的目录

- **禁止删除**`~/.antigravity-server`, 是用户常用目录
- **禁止删除**`~/.ssh`, 是用户常用目录
- **禁止删除**`~/.codex`, 是用户常用目录
- **禁止删除** docker,docker-compose数据卷

## 要求

1. 先确认当前状态, 确认现状. 因为可能有些已经正确处理了.
2. 按风险低,收益高的优先级安排. 优先处理风险低,收益高的任务.
3. 数据盘相关目录的读写泉下至少要确保当前用户可读写.
4. **必须等待明确允许**, 才执行清理.
